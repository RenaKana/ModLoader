# 运行环境与模型格式

[返回首页](../README.md) · [使用指南](usage.md) · [开发与构建](development.md)

## 选择运行环境

模型文件不能由任意程序通用加载。先根据模型作者的说明确认格式和支持的运行程序，再在 ModLoader 中选择对应后端。

| 运行后端 | 模型入口 | 当前集成位置 |
| --- | --- | --- |
| llama.cpp | GGUF；图片输入还需匹配的 mmproj 视觉投影文件 | Windows 原生程序 |
| Strata | 支持的 MoE 权重和配套准备文件；不同模型家族使用对应引擎 | Windows 服务和原生引擎 |
| Transformers | 完整本地 Hugging Face 模型目录 | Windows 独立 Python 环境，`transformers serve` |
| vLLM | 完整本地 Hugging Face 模型目录 | WSL2 独立环境 |
| SGLang | 完整本地 Hugging Face 模型目录 | WSL2 独立环境 |
| NInfer | `.ninfer` 文件，或按匹配配方转换的 Hugging Face 源目录 | WSL2；当前托管构建面向 RTX 5090 |
| SparkInfer | 支持的 GGUF 或原生 NVFP4 目录，及配套分词器、可选草稿模型 | WSL2；当前托管构建面向 RTX 5090 |
| 自定义引擎 | 所登记服务实际支持的文件或目录 | Windows 或 WSL2 |

具体模型架构、显卡、驱动和精度支持由所选运行环境决定。模型加载使用本地文件，不会在加载时自动补下载模型资源。

安装界面从官方目录读取可用版本和运行类型。固定源码构建及特定版本依赖配方保存在 [catalog.py](../core/modloader/backends/catalog.py)、[source_builds.py](../core/modloader/backends/source_builds.py) 和 [sglang_versions.py](../core/modloader/backends/sglang_versions.py)，以安装任务的实际清单为准。

## Windows 环境

### llama.cpp

导入已有环境时选择 `llama-server.exe`。GGUF 分片需要完整保留；图片输入在加载配置中开启，并选择与主模型匹配的“视觉投影器”。

“GPU 层数”决定卸载给显卡的层数。已知模型层数时，控件按 GGUF 元数据给出真实上限；明确的 CPU 环境上限为 0。自动、全部及导入的特殊值按对应引擎语义保留，不按推荐值替换。

“加载预估”使用同版本 `llama-fit-params`。Host 上下文和计算缓冲计入内存；模型缓冲保留为参考，不直接当作物理内存相加。MTP 草稿和缓冲的额外占用不包含在基础估算中。

### Strata

导入时选择 Strata 根目录，Python 路径可留空自动检测，也可以导入其已有 JSON 启动配置。安装界面分别显示发行版本和实际引擎版本，不用 Python 服务包版本代替引擎身份。

加载时会复用本模型已有的准备文件，或在首次加载时离线生成 pack 和 tokenizer，然后继续启动。命令预览与配置检查不触发实际准备。准备可取消，原权重保留；原始权重和被引用的配套文件需要留在原路径。

DeepSeek V4.1 需要选择对应的 DeepSeek 环境，不能复用 Qwen 引擎。加载配置会显示 Engram、元数据和可选 DSpark 入口；发现多个配套文件时需要明确选择。部分量化缺少哈希元数据时，还需要同版本 UD-Q8_K_XL 第 1 分片。当前 DeepSeek 路径为文本单请求，使用 DSpark，不套用 Qwen 的视觉、KV、MTP 或专家常驻选项。

#### 启动专家预取

托管 Strata 环境可点击“准备启动预取”，也可以在安装或更新时一并准备。完成后，在加载配置的“文件与启动选项”中开启“启动专家预取”；普通配置不自动启用。

构建需要 Git、CMake、Ninja、Visual C++ 和 CUDA 工具链。非标准安装位置可在数据目录下的 `runtime-tools/strata-prefetch.json` 配置 `cuda_root`、`cmake`、`ninja`、`vcvars`、`git` 的绝对路径。

构建脚本是 [build-strata-prefetch.ps1](../scripts/build-strata-prefetch.ps1)，补丁位于 [patches/strata-prefetch](../patches/strata-prefetch)。优化引擎与原引擎并存，按实际 `engine/BUILD.json` 的提交、版本和构建身份匹配。升级时补丁或原生检查失败会中止准备，保留原环境；切换到未准备预取的环境时，可以保留原环境或明确关闭预取后切换。

### Transformers

使用完整本地 Hugging Face 模型目录，导入环境时选择独立环境中的 `transformers.exe`。当前 `serve` 适配器没有接入原生 MTP，也没有资源占用预估。

## WSL2 与模型位置

WSL2 是 Windows 中运行 Linux 环境的功能。只使用 Windows 后端时不需要它；vLLM、SGLang、NInfer 和 SparkInfer 的当前集成需要 WSL2。

“运行环境”按“Windows 本机”和“WSL2 / Linux”分组。应用安装的 WSL 环境共用专用 ModLoader 发行版，各引擎目录独立；也可导入你已有发行版中的环境。外部环境只登记和检查，文件仍由你管理。

导入已有 Linux 环境时选择发行版，填写来宾中的程序绝对路径，不填写外层 `wsl.exe` 命令。读取发行版列表不会启动 WSL，检查或浏览来宾文件时才访问它。

### 模型可以放在哪里

- **Windows 本机**：模型保持 Windows 路径。WSL 引擎使用时，按目标发行版的实际挂载规则转换。
- **WSL2 / Linux**：模型记录发行版和 Linux 绝对路径，保留大小写。它只能供同一发行版的 WSL 引擎使用，不自动跨发行版复制，也不直接交给 Windows 引擎。

模型的“存储管理”支持已识别 HF、GGUF 和 NInfer 模型在 Windows 与 WSL 之间迁移。先停止模型，再检查目标目录和关联配置：

- “迁移到 WSL”默认复制到专用发行版的 `/opt/modloader/models/<模型名称>`，兼容的同发行版配置使用新登记。
- “移到 Windows”在所选目标中建立模型目录，并调整关联 WSL 配置的路径。
- 勾选“完成后删除源文件”时，先校验副本并更新登记，再按清单删除；有其他引用的源文件会保留。未勾选则两端文件都保留。

迁移任务可停止，中断后需要重新检查目标再重试。普通“移除模型”仍与文件迁移分开。

### 环境生命周期与网络

更新先在新目录安装和验证，再由你选择哪些加载配置切换。卸载只处理归属匹配的引擎目录，保留共享发行版；环境正在使用时不能移除。停止模型只清理该实例的 Linux 进程组，不关闭整个 WSL 发行版，也不执行全局 `wsl --shutdown`。

需要下载依赖时，安装任务会检查代理在来宾中是否可达。WSL 的 NAT 模式下，Windows 的 `127.0.0.1` 通常不是来宾可用的代理地址；不可达时任务报错，不会自动更换代理。已下载文件优先使用宿主缓存。

### SGLang

使用完整本地 HF 目录。自动安装采用版本化配方，包含独立 CUDA/JIT 工具链；缺少本地内核时会报错，不在模型加载阶段自动联网补下载。缓存位于各自环境内。

“原生 MTP / NEXTN”检查权重中的 MTP 张量，不下载独立草稿模型。草稿候选为 1 时，验证窗口必须等于草稿步数加 1。专家分页和 CUDA Graph 选项按实际版本显示，旧版本不套用新版本的参数。

### NInfer

已有 `.ninfer` 可以直接导入，并检查工件组件。使用 HF 源时，需要明确选择官方转换方案、转换设备及准备组件；输出写入独立派生目录，保留原权重。GGUF 不能反向恢复为转换器要求的完整 HF 源。

“配套分词器目录”需要同时包含 `tokenizer.json` 与 `tokenizer_config.json`。转换前会检查配套关系，不自动改写分词器。不同固定版本的模型结构限制按该版本执行，不把旧版限制套到所有外部环境。

原生 MTP 要求工件有 MTP 组件。识图要求工件包含 `vision`：从 HF 源准备时勾选“准备视觉组件”，加载时再开启“图像输入”。文本工件不能通过加载开关补出视觉权重。

容量参数随环境版本变化：

- 旧版“KV 容量（Token）”是 Token 数，或 `auto`。
- 新版“KV / State 共享容量”是字节容量，支持 `B`、`KiB`、`MiB`、`GiB`，或 `auto`，例如 `8GiB`。
- 切换环境后若保留了另一种单位的旧值，需先清除再按新单位设置，应用不会自动把 Token 换算成字节。

### SparkInfer

检查目标权重、本地 `tokenizer.json` 和可选草稿目录。支持的草稿方法是 DFlash2 / DSpark，不能用 GGUF 内置 MTP 权重替代。

“每轮草稿提案 Token”中，0 表示引擎自适应，1 表示最小固定提案。关闭草稿加速时保留已填路径，方便下次启用。

“服务最大输出 Token”在下次加载时设置服务级上限；留空沿用环境设置或引擎默认，非正数使用引擎默认。“生成默认值”的最大输出仍独立控制每次请求预算。当前适配走 WSL2 原生构建，不使用 Windows 包。

## 参数与加速

加载参数按后端实际语义处理，推荐值不是统一硬限制。上下文长度、并发、GPU 分配和缓存参数的合法值可能因环境不同而变化；引擎支持的自动、全部或关闭等特殊值会保留。

### 选择 GPU

“加载参数 → GPU 分配”可以点选本机识别到的设备，也可以直接填写设备列表：

- llama.cpp：卸载设备、拆分模式、分配比例及主 GPU 索引；比例按引擎设备顺序排列，全零保留原生自动分配。
- vLLM / SGLang：CUDA 可见设备、张量并行、流水线并行；点选写入 UUID，手填也可使用 CUDA 索引，列表顺序决定进程内可见顺序。
- Strata：原生 GPU 索引列表；清空显式值后继续继承导入配置。
- NInfer / SparkInfer：CUDA 可见设备，不额外声明引擎未提供的并行模式。

逐卡资源预估按 UUID 或唯一 PCI 地址匹配容量，不把不同环境的 CUDA 编号混为同一设备。没有匹配到设备时显示“容量未读取”。vLLM / SGLang 的显存预算与单序列缓存参考分别展示，实际缓存池由引擎决定。

### MTP 与草稿加速

“MTP 推测加速”会检查权重内置张量或配套文件，不按文件名推断。开启开关不会自动下载或转换资源；Strata 只自动推荐同一模型登记下的配套 MTP 文件，跨模型手动选择需保证来源版本一致。

Strata 的 MTP 验证窗口最多包含当前 Token 加 7 个预测 Token，“最大预测 Token”因此为 1–7；其他引擎不套用这个上限。支持长查表的 Strata 环境另有更长验证窗口，MTP 预测长度仍单独受限。

需要工具解析器的引擎，可以在“启动参数”中设置其文档要求的 `--enable-auto-tool-choice`、`--tool-call-parser` 等选项。模型路径、监听地址和端口由管理器维护；视觉、加速资源使用对应控件设置，编辑器会按当前后端提示保留项。

## 自定义引擎

已有可以在命令行启动的 OpenAI 兼容服务时，可在“运行环境 → 导入运行环境”中选择“自定义引擎”。保存只登记模板，加载模型时才运行程序；请仅使用可信入口。

1. Windows 选择 EXE，Python 服务选择对应环境的 `python.exe`。
2. WSL 选择发行版和 Linux 程序绝对路径，不填外层 `wsl.exe`。
3. 在“启动参数模板”中每行填一个参数项，选项和值分行，含空格的路径不加引号。

例如，服务本身接受以下选项时，可以填写：

```text
--model
{model_path}
--host
{host}
--port
{port}
```

选项名称需要与该服务实际接口一致。必填占位符 `{model_path}` 和 `{port}` 分别展开为所选模型路径、ModLoader 分配的端口；`{host}` 固定为 `127.0.0.1`。还可使用 `{model_dir}`、`{alias}`、`{context_length}`，最后一项需要在加载配置中填写上下文长度。

参数按 argv 直接传给程序，不执行 shell 拼接。Python 模块入口可在开头逐行填 `-m` 和模块名；脚本入口填目标平台的绝对路径。

“服务与环境选项”设置工作目录、非敏感环境变量、就绪检查和对话路径，默认使用 `/v1/models` 与 `/v1/chat/completions`。环境变量明文保存在数据库，不要在此填写密码或密钥。只勾选服务实际支持的生成参数，流式用量统计也按需开启。

保存后，到模型库新建配置，选择“自定义引擎”和模板，即可加载、对话、看日志和停止。其他格式可在“导入模型”中勾选“按自定义模型路径登记”；此方式不识别格式、不检查权重完整性，目录大小不遍历统计。

自定义入口不安装依赖、不转换模型，也不提供引擎专属预估和监控。移除模板只移除登记，不删除启动程序或模型。
