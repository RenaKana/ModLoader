# 使用指南

[返回首页](../README.md) · [运行环境与模型格式](backends.md) · [开发与构建](development.md)

## 启动与退出

桌面包完整解压后，运行 `ModLoader.exe`。源码启动需要先完成[开发准备](development.md)。

关闭主窗口默认进入系统托盘，不停止模型或正在进行的对话。托盘菜单中的“退出并停止模型”会完全退出，并停止由 ModLoader 启动的模型。“设置 → 文件与应用”可以关闭“关闭到系统托盘”。

整体缩放使用 `Ctrl +`、`Ctrl -`、`Ctrl 0` 或视图菜单；文字大小在设置中单独调整。

## 准备运行环境

“运行环境”中的每个环境都是一套实际运行模型的程序。模型文件和运行环境要匹配；不知道如何选择时，先看[格式对照](backends.md#选择运行环境)。

- **安装新的环境**：在对应卡片点击“安装环境”，选择“官方版本”和“运行类型”，再点击“开始安装”。安装所需的下载和依赖处理会在后台继续，进度在本页的安装任务中查看。
- **使用已有环境**：点击“导入已有”或“导入运行环境”，选择后端并填写运行入口。例如 llama.cpp 选择 `llama-server.exe`，Strata 选择含服务和引擎的根目录。
- **查找已有环境**：点击“自动搜索环境”，检查搜索结果后再选择导入。

应用安装的环境可以更新、切换配置和卸载。更新会新建独立环境，旧环境保留；运行中的模型继续使用原环境，切换后的配置在下次加载时生效。外部导入的环境由你管理，“移除登记”保留原文件。

模型下载任务在“发现模型”，环境安装任务在“运行环境”。下载阶段可以暂停、继续或停止；解压、依赖安装阶段只能停止。退出应用后未完成任务会显示已中断，可在下次启动后重试。

## 添加模型

### 导入电脑上已有的模型

在“模型库”选择：

- **导入模型**：选择 GGUF 或 `.ninfer` 模型文件。
- **导入文件夹**：选择模型根目录，递归查找 GGUF、NInfer 和完整 Hugging Face 模型目录；分片会合并登记，已导入模型会跳过，失败项单独列出。
- **导入启动配置**：导入已有的 llama.cpp 启动脚本或 Strata JSON 配置。

导入保留原文件，只记录其位置。分片模型要保留全部分片；完整模型目录也需要配置和分词器等配套文件，不能只留下最大的权重文件。

### 搜索并下载模型

“发现模型”支持 Hugging Face、ModelScope，也支持直接链接下载。

1. 搜索模型，或点击“打开模型仓库”输入仓库信息。
2. 打开“模型介绍”，阅读模型作者的使用要求和许可。
3. 在“下载文件”中选择需要的版本和文件，检查清单后开始下载。

同一仓库可能有不同大小、格式和压缩程度的模型，不需要全部下载。分片和必需配套文件会按所选模型组合；图片输入所需的视觉文件默认不选，存在多个候选时需要你明确选择。

新下载文件的位置在“设置 → 文件与应用 → 模型下载目录”中修改，不影响已登记模型。受限仓库需要在“设置 → 模型源凭据”中填写相应 Token，并先取得模型作者授予的访问权限。

## 创建加载配置

选中模型，在“加载配置”中点击“新建配置”。

1. 选择“运行后端”和已安装的“运行环境”。
2. 填写“配置名称”和唯一的“API 模型名称”。配置名称方便你区分用途；API 模型名称供其他软件调用。
3. 根据需要调整“加载参数”和“生成默认值”，点击“保存配置”。
4. 点击“加载模型”，等待状态变为“运行中”。准备或加载失败时点击“日志”查看原因。

**上下文长度**决定一次请求中可处理的对话和输出规模，通常越大越占内存或显存。界面中的 Token 是模型统计文本的单位，不等同于汉字数。首次运行可先用较短的上下文，确认可用后再调整。

“加载预估”用于比较当前配置的资源需求，超出容量时仍可保存和尝试加载。`待估算`、`估算失败`、`无法估算` 分别表示尚在等待、计算出错和当前没有可用估算。实际占用还取决于模型、环境和运行过程。

同一模型可以保存多套配置，不会重复复制权重。“复制配置”沿用原配置的参数和资源路径，并生成独立名称；直接“新建配置”不会继承另一套配置的全部参数。运行中的配置修改后需要停止并重新加载。

“启动参数”页可以查看、编辑和复制实际启动参数。模型路径、服务端口和部分配套资源由加载配置管理；编辑器会显示不能覆盖的参数及错误。高级设置见[参数与加速](backends.md#参数与加速)。

## 在内置对话中使用

进入“测试对话”，选择已加载模型。点击“新建会话”开始另一段对话；“对话历史”可以打开已有记录。切换会话时，正在生成的内容继续写回原会话。

“对话参数”可以调整本会话的生成设置、系统提示词和工具定义。保存为预设后可在其他会话复用；勾选“用于新会话”将其设为默认。修改当前会话不会自动改写已有预设或其他会话。

### 图片和文档

将附件拖入对话窗口，或使用输入区的附件按钮。

- **图片**：需要模型和加载配置支持“图像输入”；部分模型还需选择匹配的“视觉投影器”。点击图片可放大，滚轮缩放，左右键切换同条消息中的图片，`Esc` 关闭。
- **文档**：支持文本、Markdown、源码、PDF 和 DOCX。提取的正文可展开检查，随后作为文本发给模型；扫描版 PDF 需要先进行文字识别。

回复支持 Markdown、代码高亮、公式、Mermaid、Graphviz，以及静态 HTML/SVG 预览。HTML 的“浏览器打开”会在系统浏览器中打开原文件，可能运行其中的脚本，只打开可信内容。应用内预览禁用脚本。

### 长对话与历史

“自动压缩上下文”默认开启：接近已知容量时，用当前模型概括较早内容，保留最近完整一轮。原始历史和 Markdown 导出不变；后续请求使用摘要和保留的消息。可以在“对话参数”中查看摘要或“恢复完整上下文”，也可以手动压缩。

编辑旧消息后重新发送会清除其后的内容；重试历史回复也会在确认后清除后续消息，不创建分支。会话标题旁可导出 Markdown、清空消息或删除会话。

### 联网搜索是可选的

输入框底部的地球图标提供“关闭”“自主搜索”和“检索后回答”。新会话默认选择“自主搜索”；不需要联网时选择“关闭”。

- **自主搜索**：模型决定何时搜索网页、搜图和阅读，需要模型及聊天模板支持原生工具调用。
- **检索后回答**：先生成检索词、选取和阅读来源，再回答，不要求原生工具调用。

先在“设置 → 联网服务”中配置自己的服务地址和凭据，并使用对应测试按钮检查。支持 SearXNG、DeepSeek、Tavily、Brave Search、Serper 和 OpenAI；网页读取也可选择本地抓取。SearXNG 需要服务端开启 JSON 输出；默认地址指向本机，需自行提供搜索服务。“高级路由”可以为网页搜索、搜图和读取分别设置首选及备用渠道；默认没有备用渠道。

启用后，检索词和目标网页地址会发给所选服务，收费服务的测试和实际调用均可能计费。以图搜源使用 SauceNAO：在“自主搜索”中，模型调用该工具时会直接发送所选对话图片，不再逐次确认。

本地抓取只读取公开 HTML 和文本，不执行网页脚本，不读取内网、带凭据的地址、PDF 或二进制文件。通过应用代理处理 Clash Fake-IP 解析时，会向 Google DNS over HTTPS 查询目标域名的真实公网地址。

默认每轮工具调用预算为 25 次、并行数为 3，可在“对话参数”修改；联网与基础工具共用预算。达到预算后停止并保留已有结果。搜索、阅读和生成期间均可点击“停止”。

### 本地文件工具

扳手图标启用计算和时间工具。若要让模型读写文件，在“对话参数 → 本地工具目录”中选择一个目录。

模型只能访问授权目录。创建或修改文本前会展示路径和内容差异，点击“允许写入”才执行；不执行命令或删除文件。文件引用可以显示为附件，但不会自动把图片像素加入模型的视觉输入。撤销或更换目录授权后，原引用会重新检查访问权限。

## 连接其他软件

在“设置 → 本地 API”复制 Base URL 和 API Key，在其他软件中选择 OpenAI 兼容的 Chat Completions 接口，并填入加载配置的“API 模型名称”。默认 Base URL 是 `http://127.0.0.1:12340/v1`；修改端口后需要重启 ModLoader。

接口提供：

- `GET /v1/models`：列出已加载、可用的模型。
- `POST /v1/chat/completions`：普通或流式对话。

不提供 Responses 接口。外部软件需要自行提交对话历史和执行工具；此接口不自动套用内置会话、联网搜索或本地文件工具。API 仅监听 `127.0.0.1`，不能直接供其他电脑访问。

“API 示例”中有可复制的 cURL 和 Python 接入示例。密钥只填入你信任的软件；更换本地 API Key 后，原客户端也需要同步更新。

## 查看运行状态

“运行监控”选择一个运行实例，查看生成速度、请求记录和硬件使用情况；“小窗监控”可保持置顶。主窗口最小化或进入托盘后，小窗仍会更新。关闭小窗不停止模型。

- **Prefill** 是处理输入的阶段；**Decode** 是生成输出的阶段，两者速度分别统计，单位为 Token/s。
- Decode 当前速度使用同一请求约 3 秒的有效采样窗口；平均速度优先采用引擎原生数据，否则按有效采样统计。没有来源的数据显示 `—`。
- 外部 API 的每个 HTTP 请求单独列出。内置对话可查看整轮及其子请求；工具等待不会当作持续生成速度。
- 输入 Token 包含缓存命中，缓存不重复计入总量。总 Token 为输入加输出；缺少缓存计量时命中率未知。
- 查看历史时新请求不会抢走选择。“刷新到最新”回到今天、清除记录实例筛选并恢复跟随最新调用。

硬件曲线保留本次运行最近 60 秒的数据，缺测处断线。上下文占用是模型报告的 Token 计数，不是缓存实际占用的字节数。不同运行环境提供的指标不同。

CPU/GPU 温度由独立读取进程获取，完全启动应用时会请求一次 Windows 管理员授权。取消授权不影响模型加载；需要时可在温度详情点击“重试温度读取”。首次读取 CPU 温度还需要单独安装[官方 PawnIO 驱动](https://github.com/namazso/PawnIO.Setup/releases/tag/2.2.0)，应用不会自动安装。

## 数据、备份与模型存储

默认数据位置取决于启动入口：

- 直接启动桌面包中的 `ModLoader.exe`：默认使用该程序旁的 `data` 目录，也可通过 `MODLOADER_DATA_DIR` 指定位置。
- `Start-ModLoader-Dev.cmd`：默认使用项目根目录的 `data`，保留已有的 `MODLOADER_DATA_DIR` 设置。
- `Start-ModLoader.cmd`：先指定项目根目录的 `data`；可选的本地启动覆盖见[开发文档](development.md#首次启动源码版)。

会话正文、思考、附件、工具记录、草稿和设置保存在 `modloader.sqlite3`，是本地明文数据，不自动过期。密钥保存在 Windows 用户绑定的加密文件中，不能假定复制到另一台电脑或账号后仍可解密。

备份前先从托盘完全退出应用，再备份整个数据目录。原地导入的模型和运行环境可能位于数据目录外，需一并保留；恢复时也要保持其路径可用。共享问题报告前检查日志、导出和截图中的私人路径与内容。

### 调用记录

“设置 → 本地 API”默认开启“保存调用记录”，保留时间为永久，也可改为 7 天或 30 天。默认记录目录为数据目录下的 `logs/api-requests`。

调用记录保存请求身份、状态、用量和工具名称，不保存提示词、回复正文、工具参数、工具结果或密钥；内置会话本身仍按上述方式保存。修改记录目录不会移动旧文件，历史入口读取当前配置的目录。有限保留期按包含今天的本地自然日计算。

### 移动和移除模型

需要迁移模型时，先停止模型，再使用模型的“存储管理”检查目标和关联配置。Windows 与 WSL2 之间的迁移规则见[WSL2 与模型位置](backends.md#wsl2-与模型位置)。

普通“移除模型”默认只移除登记及加载配置，文件保留。Windows 模型可以另外勾选“同时删除磁盘中的模型文件”，确认待删除清单后才执行；该删除不能由应用撤销。WSL 模型的普通移除保留原文件。

## 排错顺序

| 遇到的情况 | 下一步 |
| --- | --- |
| 导入没有识别到模型 | 查看扫描结果；确认分片齐全，Hugging Face 目录包含配置、分词器和权重，而非仅一个权重文件。 |
| 没有可选运行环境 | 安装或导入与模型格式、模型位置匹配的环境；WSL 内模型需要同一发行版的环境。 |
| 加载失败或一直在准备 | 打开该配置的“日志”，检查缺少的配套文件、模型支持情况和实际准备进度；可取消准备或停止实例。 |
| 内存或显存不足 | 选择较小模型，降低上下文；llama.cpp 可减少 GPU 层数。根据日志调整，不必只依赖资源预估。 |
| 本地对话能用，联网失败 | 先关闭联网确认本地路径，再到“联网服务”检查地址、凭据、额度和所选模式。 |
| 外部软件无法连接 | 检查模型是否运行、三项接入设置是否一致；若设置提示 API 端口被占用，改端口后重启。 |
| 提示“未保存” | 点击“重试保存”；它只补存记录，不会重新请求模型。检查数据目录权限和剩余磁盘空间。 |
| 下载或环境安装失败 | 查看任务详情及“网络代理”；访问受限仓库时检查凭据与访问权限，再重试失败任务。 |
